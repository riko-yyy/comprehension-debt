# 0014: 毎朝 GitHub Actions でレポートを作り、GitHub Pages に公開する

- 日付: 2026-10-17
- ステータス: 提案

## 背景

Phase 6 では、Phase 5 のレポート（ADR 0012）を毎日自動で作り直し、手元で `report` を打たなくても見られるようにする。
λ=1、併走倍率=0.5 は暫定（ADR 0011）で、毎日スコアを眺めながら上位10件の並び順を見直したい。
そのためには、複数のリポジトリのレポートが決まった場所に並んでいる必要がある。

## 決定

- 対象はリポジトリのルートの `targets.yml` に並べる。`name`（公開先のディレクトリ名）と `repo`（`owner/name`）の組
- `npm run site` が、対象を一時ディレクトリに全履歴つきで `git clone` し、`report --out site/<name>` を実行して、最後に一覧ページ `site/index.html` を書く
- `.github/workflows/report.yml` が、毎朝6時（JST）と手動実行で `npm run site` を動かし、`site/` を GitHub Pages に公開する
- 対象は公開リポジトリだけにする。clone にトークンが要らない
- 対象の `understanding.yml` と `.understanding/acks.jsonl` は、その対象のリポジトリにあるものが使われる
- 1つでも失敗したら（clone できない、`report` が落ちる）、その回は公開しない。前の日のページが残る

作らないもの: 日ごとのスナップショット（履歴の比較）、通知、PR コメント、非公開リポジトリの対象化。

## 検討した選択肢

- `actions/checkout` で対象を取得する — 既定で最新1コミットしか取らない（ADR 0007 の既知の注意点）。`fetch-depth: 0` を毎回書き忘れないようにするより、`git clone` で全履歴を取るほうが確実。手元でも同じ `npm run site` で確かめられる
- 対象ごとにジョブを分ける（matrix） — 一覧ページを書くために結果を1か所に集め直す必要がある。対象は5つほどなので、1つのジョブで順に回せば足りる
- 失敗した対象だけ飛ばして公開する — 一覧から黙って消えると気づけない。今は対象が少ないので、全部止めて Actions の失敗として見えるほうがよい
- 非公開リポジトリも対象にする — 読み取り用トークンの管理が要る。公開ページに非公開リポジトリのファイルパスと「理解できていない場所」が載ってしまう

## 結果

- 毎朝、`https://riko-yyy.github.io/comprehension-debt/` に全対象の最新のレポートが並ぶ
- 公開ページには、対象リポジトリのファイルパスと、理解できていない場所が誰でも見える形で載る。対象が公開リポジトリなので、コード自体はもともと見える
- GitHub の定期実行は混んでいると遅れることがある。また、公開リポジトリで60日間コミットがないと定期実行が止まる。止まったら Actions の画面から有効に戻す
- 日ごとの変化を見たくなったら、スナップショットを別 ADR で足す
- 有効にするには、人間が Settings → Pages の Source を「GitHub Actions」にする
