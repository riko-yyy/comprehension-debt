# 0011: 危険度は「重要度 × 理解していない度合い × 変更頻度」で出す

- 日付: 2026-10-16
- ステータス: 提案

## 背景

Phase 4 では、理解スコアだけでなく「どこが本当に危ないか」を出す。
スコアが低くても、重要でないファイルや、もう触られていないファイルは急いで読む必要がない。
逆に、重要で頻繁に変わっているのに理解していないファイルは、事故が起きやすい。

## 決定

```
危険度 = 重要度 × (1 − 理解スコア) × 変更頻度
```

- **重要度**: 対象リポジトリの `understanding.yml` の `core:` で宣言する。書き方は `ignore:` と同じパターン（ADR 0008）
  - core に一致したら 1、それ以外は 0.3
  - `core:` がなければ、すべて 1 として扱い、注意を出す
- **変更頻度**: 直近90日にそのファイルを変えたコミットの数を `log1p` で縮め、最大のファイルを 1 とする割合
  - 対数で縮めるのは、変更回数の多いファイルが極端に強くならないようにするため
  - 90日は vision.md の時間窓に合わせた
- `danger <repo-path>` コマンドで、危険度の上位10件を出す（危険度が 0 のものは出さない）

## 検討した選択肢

- 重要度を宣言せず、依存グラフの中心性や co-change から自動で推定する — vision.md の P2。段階1では手で宣言する
- core 以外の重要度を 0 にする（core だけを危険地帯に出す） — core を書き漏らしたファイルが永久に見えなくなる
- 変更頻度に生の回数を使う — 1つのファイルに変更が集中しているリポジトリで、他がすべて 0 近くに潰れる
- 危険とみなす閾値を決める — 上位10件という見せ方で足りる

## 結果

手元の5リポジトリで出した上位10件で、λ と併走倍率を変えて比べた（tekito-uranai）。

- 併走しかないリポジトリでは、効くのは λ × 併走倍率の積だけ（λ=1, pair=0.5 と λ=0.5, pair=1 は完全に同じ結果）
- λ を大きくすると、どのファイルもスコアが 0 近くになり、並び順が変更頻度だけで決まる。小さくすると、スコアの差が並び順に効く
- 上位10件の顔ぶれは λ=0.5〜3 でほぼ変わらず、順番が少し入れ替わるだけ

λ と併走倍率の値は、上位10件を人間が眺めて納得できるかで確定する（ADR 0007 で保留していたもの）。
CSS、README、ADR などのドキュメントも上位に入る。理解の対象とみなすか（`ignore:` するか、core 以外として扱うか）は、リポジトリごとに `understanding.yml` で決める。
