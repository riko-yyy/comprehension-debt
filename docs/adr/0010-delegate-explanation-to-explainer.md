# 0010: 理解の補助（説明）はこのツールで作らず、explainer に任せる

- 日付: 2026-10-15
- ステータス: 提案

## 背景

理解スコアで「どこを理解していないか」は分かるようになった。しかし、「どう追いつくか」を助けるものがない。
測るだけでは、低いスコアを眺めて気が重くなるだけになる。「測る → 読む → ack する」の真ん中が空いている。

このツールの中で埋める案として、次の3つを考えた。

1. 最後に理解した時点からの差分を出す `catchup` コマンド
2. 危険地帯を「今週読むリスト」として出す
3. 差分から質問を作り、答えられたら ack する（一問レビュー bot）

一方で、[mizchi/explainer](https://github.com/mizchi/explainer) という Claude Code プラグインがある。
特定の一人の読み手に向けて、その人がまだ知らないことだけを説明する文書を書き、図や出力例をツールで検証する。
問題意識（AI が書く速さに、人間の理解が追いつかない）がこのツールと同じで、実際に試して使えると判断した。

## 決定

- 説明（理解の補助）はこのツールで作らず、explainer に任せる
- このツールは「測る」ことと、「何を読むべきか」のデータを出すことに集中する
  - 案1の差分は、説明を作るのではなく、explainer に渡す材料として Phase 5 の JSON 出力に含める
  - 案2は、Phase 4 の `danger` の延長として作る
  - 案3は作らない。explainer の文書を読んでから `ack` する使い方で代える
- 流れは「`score` / `danger` で見つける → explainer で説明を読む → `ack` で記録する」
- `acks.jsonl` は、explainer のペルソナ（読み手がすでに知っていること）の材料にもなる

## 検討した選択肢

- 案1〜3をこのツールの CLI として作る — 説明の質と検証の仕組みを自前で作ることになり、段階1の範囲（ADR 0005）を大きく超える
- 説明は何も用意しない — 測るだけで終わり、スコアが改善する手段が「自分で読む」しかない

## 結果

説明の仕組みを作らずに済み、このツールは小さいままでいられる。
外部のプラグインに頼るので、explainer の変更や停止の影響を受ける。ただし、つながりは「人間が説明を読んで ack する」だけなので、別の手段に置き換えやすい。
explainer は `comprehension-debt` に `local` スコープで入れている（他のリポジトリでは使えない）。全リポジトリで使うなら `user` スコープで入れ直す。
質問に答えたら ack する（申告に頼らない理解の確認）は、explainer で代えたため当面作らない。ack のごまかしが問題になったら、改めて考える。
