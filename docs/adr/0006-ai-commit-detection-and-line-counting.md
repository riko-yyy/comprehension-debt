# 0006: コミットの由来の3分類と変更行数の数え方

- 日付: 2026-09-25
- ステータス: 採用

## 背景

Phase 1 では、コミットごとに誰が書いたかを判定し、ファイル単位で変更行数を集計する。
最初の対象 `design-doc-repo` を確認すると、AI が関わるコミットは2種類あった。

- author が人間（`riko_yyy`）で、`Co-authored-by: Claude Sonnet 5 <noreply@anthropic.com>` が付いたもの（11件）
- author そのものが `Claude <noreply@anthropic.com>` のもの（1件）

前者は、人間がターミナルで Claude Code と一緒に作業した結果。後者は、パイプラインが自動で作った結果。
一緒に作業していれば、ある程度は理解している可能性がある。人間か AI かの2分類では、この違いが消えてしまう。

## 決定

### 由来の3分類

| 分類 | 条件 | 意味 |
|---|---|---|
| autonomous（自律） | 作者名またはメールアドレスが AI のパターンに一致する | AI が人間の手元を離れて単独で書いた |
| pair（併走） | author は人間で、`Co-authored-by` のどれかが AI のパターンに一致する | 人間が AI と一緒に作業した |
| human（人間） | 上のどちらでもない | 人間だけで書いた |

パターンは `src/classify.ts` の `AI_PATTERNS` に置く（`[bot]`、devin、claude、`noreply@anthropic.com`、copilot、cursor）。

pair を理解度にどれだけ効かせるか（autonomous に対する倍率）は、Phase 2 でスコアを眺めて決める。
併走していても、コードを読んだかどうかは git に残らない。そのため、倍率は 0（完全に理解している扱い）ではなく、0 と 1 の間の値にする想定。

### 変更行数の数え方

- `git log --no-merges --numstat -M` を使う。マージコミットは行数が二重に数えられるので除く
- 変更行数 = 追加行数 + 削除行数
- リネームは追いかけ、リネーム前の変更も今のパスに合算する
- バイナリファイルと、HEAD に存在しないファイル（削除済み）は集計しない

## 検討した選択肢

- 人間／AI の2分類で、共同作成コミットを AI とみなす — 最初はこれで実装した。しかし、併走して理解しながら作ったコードと、任せきりのコードの区別がつかない
- 2分類で、共同作成コミットを人間とみなす — `design-doc-repo` ではほぼ全部が人間扱いになり、指標にならない
- `git blame` で今残っている行を数える — 削除や書き換えの量が見えなくなる。重いので Phase 2 以降で必要なら検討する

## 結果

作者名や trailer を付けない AI の使い方（手でコピペするなど）は検出できない。
AI エージェントの設定次第では、自律で動いたのに人間の名前でコミットされ、pair に分類されることがある。
`package-lock.json` のような自動生成ファイルも、他のファイルと同じように数えられる。
Phase 2 でスコアを眺めて邪魔になったら、除外ルールを別 ADR で決める。
