# 0013: 理解の手法は利用者に任せる（ADR 0010 を置き換える）

- 日付: 2026-10-16
- ステータス: 採用

## 背景

ADR 0010 では、説明（理解の補助）をこのツールで作らず、explainer プラグインに任せると決めた。
「`score` / `danger` で見つける → explainer で説明を読む → `ack` で記録する」という流れを、このリポジトリとして推していた。

しかし、どうやって理解するか（コードを読む、explainer などの道具で説明を書かせる、人に聞く、ペアで書き直す）は人それぞれで、ツールが決めることではない。
リポジトリを公開するにあたり、特定の道具を前提にした書き方は外したい。

## 決定

- このツールは「どこを理解していないか」を測り、理解するための材料を出すところまでを受け持つ
- 理解の手法は利用者に任せる。特定の道具（explainer を含む）を、このリポジトリとして推奨しない
- 材料は道具に依存しない形で出す。`report.json` の `changesSinceUnderstood`（最後に理解してからの変更とコミット）と、それを取り出す `git show` のコマンド
- 理解したら `ack` で記録する、という部分は変えない
- ADR 0010 は、この ADR で置き換える。ADR 0012 にある「explainer に渡す材料」は「理解するための材料」と読み替える

## 検討した選択肢

- ADR 0010 のまま explainer を推す — 利用者の手法を縛る。外部のプラグインの変更や停止にも左右される

## 結果

ツールの範囲が「測る」と「材料を出す」に絞られ、説明が明快になる。
どの道具を使うかの案内はしないので、理解の手法を持っていない人には不親切かもしれない。
質問に答えたら ack する（申告に頼らない理解の確認）は、引き続き作らない。ack のごまかしが問題になったら、改めて考える。
